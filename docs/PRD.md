## 1. 제품 개요

### 1.1 배경 및 문제 정의

해양 산업에서 항만국통제(PSC, Port State Control) 검사 시 결함이 발견되면 선박에 출항 정지(Detention) 처분이 내려지며, 대형선 기준 일일 최대 6만 달러의 용선료 손실과 징벌적 체화료(Demurrage)가 발생한다. 그럼에도 중소 선사 대다수는 수천만 원에 달하는 하드웨어 초기 도입 비용(CAPEX)을 감당하지 못해 선원의 수기 점검에 의존하고 있으며, 이는 인적 오류(Human Error)의 주요 원인이 된다.

기존 솔루션들의 한계는 다음과 같다.

- **DNV PSC Planner, RightShip 등**: 정적인 수기 체크리스트 기반으로, 선원의 인적 오류를 원천 예방하지 못하며 클라우드 의존 구조로 통신 단절 환경에서 실효성이 없음
- **3D 공간 매핑 / AR 글래스**: 흔들리는 선박 환경에서 인식 오류가 잦고, 수천만 원의 초기 하드웨어 비용 발생
- **대규모 IoT 센서**: 무거운 인프라 도입 비용(CAPEX)이 중소 선사에게 진입 장벽으로 작용

### 1.2 제품 비전

의료 영상 분석(X-ray, CT, MRI)에서 검증된 초정밀 Vision AI 기술을 해양 유지보수(MRO) 영역에 수평 전개(Spin-off)하여, 선원이 방수 태블릿 카메라로 선박 기기를 비추면 부식·누수·파손 등의 결함을 실시간으로 판독하고 PSC 규제 위반 소지를 즉시 시각화하는 **엣지 기반 오프라인 독립 구동형 진단 솔루션**을 제공한다.

### 1.3 핵심 가치 제안 (Value Proposition)

- **CAPEX Zero**: 고가 전용 장비 대신 구독형(SaaS + HaaS) 모델로 초기 비용 장벽 제거
- **Offline First**: 클라우드 없이 엣지 서버에서 완벽히 독립 구동 — 통신 단절 환경 대응
- **사이버 보안 규정 100% 충족**: IMO UR E26/E27 및 IACS 사이버 복원력 통합 규정 준수
- **Medical-grade AI**: 의료 영상 분석 수준의 정밀 Vision AI로 타사 대비 압도적 판독 정확도

## 2. 타깃 사용자 (Target Users)

### 2.1 Primary: 대형 선박 관리 회사(Ship Management)

- 수십~수백 척의 선대를 관리하며, 도입 시 일괄 적용 파급력(Leverage)이 높은 고객
- 최상위 KPI: PSC 출항 정지율 0% 유지, IT 인프라 CAPEX 최소화
- 선원 수기 점검의 Human Error로 인한 Detention 리스크에 강한 Pain Point 보유

### 2.2 Secondary: 중소형 선사

- 자체 IT 인프라를 구축할 역량이 부족하지만 디지털 점검 솔루션에 대한 수요가 높음
- 비용 부담이 가장 큰 허들 → 기본형(Basic) 티어로 진입 유도

### 2.3 End User: 선원 (Crew)

- 실제 현장에서 태블릿/스마트폰을 활용해 점검을 수행하는 최종 사용자
- IT 리터러시가 다양 → 직관적 UX, 최소한의 학습 비용 필수
- 업무 저항감을 최소화하는 BYOD 전략 적용

## 3. 시스템 아키텍처

### 3.1 5단계 기술 파이프라인

```
[1] Data Acquisition → [2] Edge Computing → [3] Mesh Network → [4] UX Interface → [5] Core Application
```

**[1단계] Data Acquisition (데이터 추출)**
- 신규 센서 설치 없이 기존 선박 장비 데이터를 활용
- 메인 운항망(OT) 보안과 충돌하지 않는 **단방향 API**로 데이터 추출
- OT 망과 IT 망의 물리적 분리 원칙 준수

**[2단계] Edge Computing (CAPEX Zero)**
- 구독형(HaaS) 산업용 초소형 미니 PC를 엣지 서버로 활용
- Vision AI 모델 및 PSC 규제 룰 엔진을 엣지에서 독립 구동
- 통신 단절(Offline) 상황에서도 완벽히 동작

**[3단계] Mesh Network (음영 극복)**
- 선박의 두꺼운 철판 구조를 뚫는 **특화 무선 메쉬망** 구축
- 기관실 ↔ 엣지 서버 간 대용량 이미지 데이터를 지연 없이 전송
- 선박 내부 Wi-Fi 음영 지역 해소

**[4단계] UX Interface (BYOD)**
- 고가 전용 장비를 강제하지 않고 선원의 **범용 방수 태블릿/스마트폰** 활용
- 진단 스캐너 뷰어 앱을 통해 카메라 화면에 실시간 오버레이 제공
- 하드웨어 도입 장벽과 현장 실무 저항감 Zero화

**[5단계] Core Application (결함 판독)**
- 의료 영상 분석 노하우가 적용된 **2D Vision AI 엔진**
- 결함(부식, 파손, 누수, 라벨 누락 등)을 실시간 판독
- 규제 위반 소지를 **2D 바운딩 박스 + 예상 PSC 결함 코드**로 즉각 시각화

## 5. 비기능 요구사항 (Non-Functional Requirements)

### 5.1 보안 (Security)

- IMO 해상 사이버 보안 규정 **UR E26/E27** 100% 충족
- IACS 사이버 복원력 통합 규정(2024.07 의무화) 준수
- OT 망과 IT 망의 **물리적 분리** 원칙 준수 — 단방향 API만 허용
- 선사의 사이버 보안 감사에 대응 가능한 보안 로그 및 감사 추적(Audit Trail)

### 5.2 성능 (Performance)

- 결함 판독 응답 시간: 카메라 프레임 기준 **500ms 이내** (엣지 서버 기준)
- 메쉬 네트워크 이미지 전송 지연: **100ms 이내**
- 엣지 서버 가용성: **99.5% 이상** (선박 운항 중)

### 5.3 호환성 (Compatibility)

- 모바일 앱: Android 11 이상 / iOS 16 이상 (방수 태블릿 지원)
- 엣지 서버: Ubuntu/Debian 기반 Linux, ARM64 및 x86_64 지원
- 네트워크: Wi-Fi 6, 802.11ac 이상 메쉬 네트워크

### 5.4 확장성 (Scalability)

- 단일 선박 내 엣지 서버 1대로 기관실·갑판 전체 커버
- 선대 규모 확장 시 육상 서버 수평 확장(Horizontal Scaling)
- 결함 유형 확장: 모듈형 AI 모델 구조로 새로운 결함 유형 추가 용이

### 5.5 사용성 (Usability)

- 선원 교육 시간: 최초 사용까지 **30분 이내** 온보딩 완료
- 결함 판독 결과: 텍스트가 아닌 **시각적(Visual) 표현** 우선
- 장갑 착용 상태에서도 조작 가능한 대형 터치 타깃

## 7. 개발 로드맵

### Phase 1: 전이 학습 및 기획 고도화 (1~2개월 차)

- 의료 영상 AI 모델 → 선박 결함 모델 전이 학습 완료

- PSC 규제 위반 룰 엔진 매핑
- Cargo Securing 결함 탐지 모듈 우선 개발 착수

### Phase 2: 엣지 인프라 패키징 및 통합 테스트 (3~5개월 차)

- 산업용 엣지 PC(미니 PC) 선정 및 AI 모델 경량화 포팅
- BYOD 태블릿용 진단 스캐너 뷰어 앱 v1.0 개발 완료
- 엣지 서버 ↔ 태블릿 간 메쉬망 로컬 통신 통합 Lab Test
- 단방향 API 데이터 추출 모듈 통합 테스트

### Phase 3: 선박 현장 PoC 및 사업화 (6~8개월 차)

- 실제 운항 선박에 시스템 탑재 및 현장 실증(PoC) 수행
- 정량적 레퍼런스 확보: 'PSC 결함 적발 0건' 및 '진단 소요 시간 단축' 입증
- B2B 유료 구독 전환(LOI) 확정
- 앵커 테넌트 확보 및 표준형 모델 론칭

### Phase 4: 글로벌 확장 (9개월~)

- Tokyo MoU / Paris MoU 관할 글로벌 선대 확장
- Kormarine 2027(부산) 등 국제 해양 전시회 시연
- DNV 등 선급과 전략적 API 연동 제휴
- IACS 사이버 보안 형식 승인(Type Approval) 획득
- 엔진 예지 보전, 정기 보안 진단 등 추가 모듈 배포

## 10. 리스크 및 완화 전략

| 리스크 | 영향도 | 완화 전략 |
|---|---|---|
| 선박 환경(진동, 습도, 염분)에서 엣지 서버 내구성 문제 | 높음 | 산업용 등급(IP65 이상) 기성품 미니 PC 선정, 현장 내구성 테스트 선행 |
| 메쉬 네트워크 철판 구조 관통 시 신호 감쇠 | 높음 | 선박 구조별 AP 배치 최적화 설계, Lab 및 실선 사전 테스트 |
| 결함 판독 오탐지(False Positive) 과다 | 중간 | 의료 영상 전이 학습 + 현장 피드백 루프를 통한 지속적 모델 Fine-tuning |
| 선원의 신기술 거부감 | 중간 | BYOD 전략으로 새 장비 학습 부담 제거, 30분 이내 온보딩 UX 설계 |
| PSC 규제 코드 변경에 따른 룰 엔진 업데이트 지연 | 중간 | 위성 통신 복구 시 자동 OTA 업데이트, 규제 변경 모니터링 체계 구축 |
| 사이버 보안 규정 강화로 인한 추가 인증 필요 | 낮음 | IACS Type Approval 선제 획득, 선급(KR, DNV) 협력 관계 구축 |

## 11. 제약 조건

- 선박 내부 OT 망에 대한 **쓰기(Write) 접근 절대 불가** — 단방향 읽기만 허용
- 위성 통신은 불안정하므로 **모든 핵심 기능은 오프라인에서 독립 구동** 필수
- 하드웨어 직접 제조 배제 — 범용 기성품(COTS) 활용 원칙
- 앱 배포 및 업데이트는 **위성 통신 복구 시 또는 기항 시** 수행
- 각 국가별 항만 데이터 규제(보건/행정) 준수 필요

## 부록: 용어 정의

| 용어 | 설명 |
|---|---|
| PSC (Port State Control) | 항만국통제 — 기항지 항만 당국이 외국 선박을 검사하는 제도 |
| Detention | 출항 정지 — PSC 검사에서 심각한 결함 발견 시 선박 억류 조치 |
| MRO (Maintenance, Repair, Overhaul) | 유지보수 — 선박의 정비·수리·점검 활동 전반 |
| CAPEX (Capital Expenditure) | 자본적 지출 — 하드웨어 등 초기 설비 투자 비용 |
| BYOD (Bring Your Own Device) | 개인 소유 기기 활용 — 선원의 범용 태블릿/스마트폰 사용 전략 |
| HaaS (Hardware as a Service) | 하드웨어 구독 서비스 — 장비를 구매 대신 월 구독료로 제공 |
| UR E26/E27 | IACS 사이버 보안 통합 규정 — 선박 내 IT/OT 망 분리 의무화 |
| MoU (Memorandum of Understanding) | 양해각서 — PSC 체제의 지역별 협력 기구 (Tokyo MoU, Paris MoU 등) |
| CIC (Concentrated Inspection Campaign) | 집중 점검 캠페인 — MoU 체제에서 특정 항목을 집중 단속하는 기간 |
| OT (Operational Technology) | 운영 기술 — 선박의 운항·기관 제어 네트워크 |
| Edge Computing | 엣지 컴퓨팅 — 클라우드가 아닌 현장 단말에서 데이터 처리 |
